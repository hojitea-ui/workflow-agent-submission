## 환경 확인 기록 (2026-10-23)

- 설치 확인: python 3.14.7, node v24.19.0, claude, opencode, agy. cargo는 없음.
- 설치 확인 시점에는 설치 여부만 확인했다(로그인·검색·이미지 권한은 미검증이었다).
- `agy models`는 모델 목록을 정상 출력했다(로그인 오류 없음). 이 호출이 인증을 거치는지, 이미지 생성이 되는지는 확인하지 않았다. **agy 이미지 생성은 지금도 성공을 확인하지 못했다**(시도한 5번 모두 이미지가 만들어지지 않았다: 4번 이미지 도구 500 오류, 1번 이미지 도구를 쓰지 않고 끝남. API_SPEC.md 10·12장).
- 2단계(모의 엔진) 실행 확인: 자동 테스트 23개 통과, 브라우저에서 주제 입력→후보 선택→질문 답변 직접 확인. 자세한 내용은 history/API_SPEC_단계별-기록.md의 8장.

### 3단계 실제 연결 확인 (2026-10-23, Claude CLI 2.1.306)

- **Claude CLI 로그인**: 이 PC에서 로그인된 상태로 호출 성공. (확인함)
- **웹 검색 (D3)**: `--restricted --tools WebSearch,WebFetch`로 `WebSearch`·`WebFetch`가 실제로 호출되고 결과가 돌아옴. 후보 조사 3회에서 검색 4-10회, 원문 열람 2-3건. D3의 "이 계정에서 실제 호출되는지" 검증은 **통과**.
- **모델·effort (D9)**: `--model sonnet --effort medium`으로 호출했고 CLI 초기화 이벤트에서 모델 `claude-sonnet-5-5`가 확인됨. 별칭 `sonnet`이 가리키는 모델은 앞으로 바뀔 수 있다.
- **세션 이어가기 (D2)**: 질문이 나온 실제 실행에서, 답변 뒤 두 번째 CLI 호출이 같은 세션 ID로 이어졌다(작업의 초기화 이벤트 2개에 고유 세션 ID 1개). 답변이 반영된 결과가 나옴.
- **실패 표시**: 로그인 없음은 실제 CLI(빈 설정 폴더)로, 검색 실패는 가짜 CLI로 화면 표시를 확인했다. **실제 검색 장애는 만들지 못해 미확인.**
- 실제 실행 중 발견한 문제(모델이 깨진 JSON을 반복해 심층 조사 실패)와 해결(`--json-schema`), 확인하지 못한 항목 전체 목록은 history/API_SPEC_단계별-기록.md의 9장.
