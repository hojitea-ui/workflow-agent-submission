- 새 `stage` 값 `proposal_ready`(심층 조사·답변 후 제안 확인). 스토리보드 단계는 이 시점에는 없었다(이후 구현됨).

- `.gitignore`에 `data/`, `.venv/` 등을 넣었다. 이 폴더는 아직 git 저장소가 아니다.

### 3단계 구현 중 AI가 정한 선택 (사용자 검토 필요)

D2·D3·D9(Claude CLI, 내장 검색, sonnet·medium)는 그대로 지켰고, 아래는 그 안에서 AI가 정한 세부 선택이다. 자세한 내용은 API_SPEC.md 9장.

- **기본 엔진**: 새 프로젝트의 기본 엔진을 `claude-cli`(실제 조사)로 바꿨다. 모의 엔진은 `run.py --engine mock`으로만 쓴다. 화면의 "모의 데이터" 표시는 모의 엔진 프로젝트에만 나온다.
- **출력 형식**: D2/D9 작성 때는 `--output-format json`을 가정했지만 `stream-json`으로 바꿨다. 검색·열람 기록(`tool_use`/`tool_result`)을 앱이 직접 읽어 진행 상황을 보여 주고 실제 검색 여부와 출처 URL을 검사하기 위해서다. 같은 이유로 프롬프트는 표준입력으로 보낸다.
- **도구 제한**: `--restricted --tools WebSearch,WebFetch`로 웹 검색·페이지 읽기만 허용한다(웹 문서 속 지시문이 PC를 건드릴 수 없게).
- **구조화 출력**: `--json-schema`를 쓴다. 실제 실행에서 모델이 중괄호 하나를 빼먹은 JSON을 반복해 심층 조사가 실패했기 때문이다.
- **앱이 모델 출력을 믿지 않는 규칙**: 성공한 검색이 없으면 후보를 쓰지 않고 `search_unavailable`로 실패, 검색·열람 기록에 없는 출처 URL은 제외, 조사 기간 밖 후보 제외, 근거 URL이 확인되지 않은 사실은 `unverified`, 원문을 열지 못했으면 확정 표시 금지. 이 기준과 임계값(후보 7개 미만이면 안내 등)은 AI가 정했다.
- **질문 규칙**: 질문은 작업당 최대 2번, 형식이 틀리면 같은 세션에서 1회만 고쳐 쓰게 하고, 이어갈 세션이 없으면 저장된 요약으로 새 세션을 연다. 모델이 질문 여부를 판단하며 항상 묻도록 강제하지 않는다.
- **'최신' 규칙의 강제**: D15를 앱이 강제한다(`titleMayUseLatest`를 앱이 계산하고 false이면 '최신'이 든 후킹 문구를 지운다). 다만 "확인된 사실 범위 안에서"라는 후킹 규칙은 프롬프트로만 요구하고 앱이 검사하지 않는다.
- **조사 기록의 사실 형식**: 사실을 문자열이 아니라 `{text, sourceUrl, status}`로 저장하고 화면에 상태 표시(확인됨/업체 주장/공개 예정/미확인)와 출처 링크를 보여 준다.
- **화면 추가**: 후보 화면에 "다시 조사" 버튼, 진행 중 경과 시간, 오류 화면의 "다시 시도"(작업 종류별).
- **시간 제한**: Claude CLI 호출 하나에 900초(`CARDNEWS_CLAUDE_TIMEOUT`).
- **강제 종료 시 하위 프로세스 정리**: 서버 프로세스를 Windows Job Object(kill-on-close)에 넣는다(`app/procguard.py`). 다른 운영체제는 아직 미지원이다. 서버 강제 종료 시 `claude`가 남는 문제(VALIDATION.md)를 고치기 위한 AI의 선택이며, 사용량을 쓰는 프로세스가 서버 없이 남지 않게 하는 쪽을 택했다.

- **웹 검색 (D3)**: `--restricted --tools WebSearch,WebFetch`로 `WebSearch`·`WebFetch`가 실제로 호출되고 결과가 돌아옴. 후보 조사 3회에서 검색 4~10회, 원문 열람 2~3건. D3의 "이 계정에서 실제 호출되는지" 검증은 **통과**.
- **모델·effort (D9)**: `--model sonnet --effort medium`으로 호출했고 CLI 초기화 이벤트에서 모델 `claude-sonnet-5-5`가 확인됨. 별칭 `sonnet`이 가리키는 모델은 앞으로 바뀔 수 있다.
- **세션 이어가기 (D2)**: 질문이 나온 실제 실행에서, 답변 뒤 두 번째 CLI 호출이 같은 세션 ID로 이어졌다(작업의 초기화 이벤트 2개에 고유 세션 ID 1개). 답변이 반영된 결과가 나옴.
- **실패 표시**: 로그인 없음은 실제 CLI(빈 설정 폴더)로, 검색 실패는 가짜 CLI로 화면 표시를 확인했다. **실제 검색 장애는 만들지 못해 미확인.**
- 실제 실행 중 발견한 문제(모델이 깨진 JSON을 반복해 심층 조사 실패)와 해결(`--json-schema`), 확인하지 못한 항목 전체 목록은 API_SPEC.md 9장.


### 4단계(스토리보드·이미지) 중 AI가 정한 선택 (사용자 검토 필요)

D16~D18은 사용자 지시이고, 아래는 그 안에서 AI가 정한 세부 선택이다. 자세한 내용은 API_SPEC.md 10장.

- **대체 방식의 해석(D16)**: "claude cli로 만들어줘"를 Claude가 **도형 도안(JSON)을 설계하고 Pillow로 그리는 단순 벡터풍 일러스트**로 구현했다. 사진·정교한 그림은 아니다. 다른 해석(예: SVG를 Claude가 직접 쓰고 변환, 이미지 생성이 가능한 다른 도구)을 원하면 바꿔야 한다. 화면에는 항상 "Claude 도안 + Pillow"로 표시한다.
- **형식 선택 화면**: 제안 화면에서 형식(목록형/이야기형, AI 추천 표시)과 표지 후킹 문구를 고르면 스토리보드를 만든다. 변경 요청과 다른 형식으로 다시 만들기를 제공하고 이전 스토리보드는 버전으로 보관한다.
- **이미지 크기·비율**: 모든 이미지는 1080×1350(D4) PNG로 맞춘다. agy 이미지 도구가 4:5를 지원하지 않아 다른 비율로 만들면 덮어 맞춰 자르되 위쪽 여백에서 자른다.
- **agy 실패 처리(agy를 켠 경우)**: 응답 상태가 SUCCESS여도 이미지 파일이 없으면 실패로 보고, 같은 실행에서는 agy를 한 번 실패하면 건너뛴다(실패 하나에 최대 3분이 걸려서). 시간 제한은 호출 하나에 420초.
- **위쪽 여백 기준**: 위쪽 30%를 비우고, 검사는 위쪽 28%의 가로 밝기 편차 12 이하를 통과로 본다(기준값은 AI가 정했다).
- **새 stage**: `storyboarding`, `storyboard_ready`, `producing`, `review`. 이미지 작업이 실패·취소돼도 stage는 `review`로 가고 만들지 못한 카드는 다시 만든다.
- **이 단계에서 미구현으로 둔 것(이후 모두 구현됨)**: 최종 승인(`/approve` final), 카드 수정(`/revisions` target cards), 글자 렌더링, 내려받기.
- **기존 데이터 보호**: 새 열·표는 `ALTER TABLE ADD COLUMN`·`CREATE TABLE IF NOT EXISTS`로 추가해 기존 `data/` 폴더가 그대로 열린다(복사본으로 확인).
- **환경 변수**: `CARDNEWS_USE_AGY`(`0`/`false`/`off`/`no`이면 agy 끔, 설정이 없으면 켜짐), `CARDNEWS_BROWSER`(SVG 캡처용 브라우저 경로), `CARDNEWS_BROWSER_TIMEOUT`(초, 기본 90), `CARDNEWS_AGY_TIMEOUT`(초, 기본 420), `CARDNEWS_AGY_HOME`(agy 대화 폴더, 기본 `~/.gemini/antigravity-cli`), 테스트용 `CARDNEWS_AGY_CMD`.

### SVG 방식 도입 중 AI가 정한 선택 (사용자 검토 필요)

D20은 사용자 지시이고, 아래는 그 안에서 AI가 정한 세부 선택이다. 자세한 내용은 API_SPEC.md 10~11장.

- **SVG를 그대로 믿지 않는다**: XML로 파싱해 허용 요소·속성만 통과시키고(스크립트·글자·이미지·외부 링크·스타일 금지), 색은 스토리보드 팔레트의 가장 가까운 색으로 강제 변환한다. 조각은 60,000자·요소 200개 이하, 그리는 요소 5개 이상. 이 목록과 한도는 AI가 정했다.
- **배경과 위쪽 여백은 앱이 그린다**: 모델은 그림 조각만 만들고, 앱이 배경 그라데이션(팔레트 4번째→3번째 색)을 깔고 그림은 y ≥ 30% 영역으로 잘라 넣는다. 그래서 위쪽 30%는 항상 비지만, 모델이 선을 넘게 그린 도형은 수평으로 잘려 보일 수 있다.
- **고쳐 쓰기**: 검증에 실패하면 이유를 알려 한 번만 고쳐 쓰게 한다(카드당 SVG 호출 최대 2번). 그래도 실패하면 그 카드만 도형 도안으로 대체한다.
- **브라우저**: Edge → Chrome 순으로 찾고 `CARDNEWS_BROWSER`로 지정할 수 있다. 사용자의 브라우저 창·프로필과 섞이지 않게 임시 프로필(`--user-data-dir`)을 쓰고 끝나면 지운다. 브라우저를 못 찾으면 Claude를 부르지 않고 바로 대체한다. 캡처 제한 시간은 90초.
- **빈 이미지 판정**: 캡처가 한 가지 색뿐이면 실패로 본다(밝기 편차 기준값 2는 AI가 정했다).
- **상태 확인**: Claude 엔진의 `GET /api/health`에 `checks.browser`(found/missing)와 `browser`를 더했다.
- **시험 방식**: 실제 agy는 호출하지 않았다. 브라우저는 가짜 브라우저로, 실제 Edge는 한 시험에서만 쓴다.

### agy 탐색 순서와 카드 선택 다시 만들기 (2026-10-23, AI가 정함)

- agy 실행 파일 탐색: `CARDNEWS_AGY`(경로) → PATH → `%LOCALAPPDATA%\agy\bin\agy.exe`. 사용자 서버에서 PATH에 agy가 없어 "찾지 못했습니다"가 난 일이 있어서 정했다. 지정 경로가 틀리면 다른 것을 몰래 쓰지 않는다.
- 카드를 골라 다시 만들 때는 고른 카드만 만든다(대기 중인 다른 카드를 몰래 만들지 않음). agy 한도를 아끼기 위해서다.

### 글자 올리기 (2026-10-23, 사용자가 답함)
- 글자는 **Pillow로 서버에서 합성**한다(HTML/CSS + Edge 캡처 대신). 이유: 추가 설치가 없고, 줄바꿈·잘림·대비를 코드로 정확히 재서 자동 검사할 수 있다.
- 미리보기에서의 수정: **카드별 값 조절 + 자동 맞춤**(제목·본문 문구, 크기, 글자색, 본문 위치, 바탕 띠 농도). 기본은 자동으로 맞추고, 잘림·겹침·대비·휴대폰 가독성은 항목별로 알려 준다.
- AI가 정한 것: 제목=위쪽 빈 영역, 본문=아래 바탕 띠(기본 농도 70), 그림 파일은 그대로 두고 `final.png`를 따로 저장, 문구 수정은 스토리보드(승인한 기획)가 아니라 카드의 글자 배치에만 저장한다.

### 카드 수정·최종 승인·내보내기 (2026-10-23, 사용자 요청 + AI가 정한 세부)
- 사용자 요청: 카드를 골라 자연어로 고치기(글만 고치면 기존 그림, 그림이 이상하면 그 카드만 다시), 고치지 않은 카드는 그대로, 고치면 최종 승인 다시, 승인 뒤 카드별 PNG·ZIP·출처·이미지 사용 기록 내려받기, 내보낸 파일 기준 누락·글자 잘림·출처·날짜 확인(확인 못 한 것은 통과 처리하지 않고 사용자 확인 사항으로 안내).
- AI가 정한 것: (1) 글/그림 구분은 Claude가 요청을 보고 정한다(kind text|image). (2) 한 번에 카드 한 장. (3) 최종 승인은 합성본 sha256 서명으로 저장해 고치면 자동으로 풀린다. (4) 내보낸 글(고친 제목·본문)은 스토리보드가 아니라 카드의 글자 배치(layout.json)에 저장하고 스토리보드(승인한 기획)는 그대로 둔다. (5) 확인 결과는 pass/fail/unchecked 세 가지이고 unchecked는 항상 "내가 확인할 것"을 붙인다. (6) 글자 잘림은 OCR 없이 계산한 배치 + 재현 일치로만 확인한다.

## agy 이미지 생성 경위 (D16·D19·D21을 순서대로 정리)
1. **처음 판단(D19)**: agy는 이미지 한 장에 사용 한도를 크게 쓴다고 알고 있었다. 모의 시험 등으로 한도가 먼저 소진돼 실제 이미지를 한 장도 못 만들까 걱정되어, agy를 기본 꺼짐으로 두었다.
2. **다시 켬(D21)**: 과제가 agy를 우선하도록 안내하고 있어서 기본 켜짐으로 되돌렸다. 한도를 아끼려고 시험에서는 실제 agy를 호출하지 않고 가짜 agy를 썼다.
3. **실제 시도 결과**: 직접 이미지를 만들어 보니 agy의 이미지 도구가 `500 Internal Server Error`로 실패했다. 7번 시도가 모두 같았다. 한 번 시도에 이미지 도구를 여러 번 호출했지만 모두 실패했고 응답 상태는 SUCCESS였다. 원인은 agy 서비스 쪽으로 추정하나 확정하지 못했다(ACCEPTANCE 9번).
4. **결과**: D16에 정한 대로 agy가 못 만들면 Claude CLI로 만든 그림(SVG + 브라우저 캡처, D20)으로 카드를 완성했다. 교안도 이 경우 claude cli로 만든 그림으로 완성해도 된다고 한다. agy가 성공했을 때 파일을 찾는 코드는 가짜 agy로만 확인했다.
