2026-10-23, 이 PC(Windows), Claude CLI 2.1.306. 요청받은 5개 상황을 재현해 기대 결과대로 되는지 확인한 기록이다.

## 시험 조건

- **앱 결과 폴더(`data/`)는 건드리지 않았다.** 모든 시험은 임시 폴더(`%TEMP%\cardnews_validation`, `CARDNEWS_DATA_DIR`로 지정)와 별도 포트(8792)에서 했다. 시험 전후로 `data/app.db`의 SHA-256 해시와 `data/` 파일 목록(경로·크기·수정 시각)을 비교했고 **둘 다 완전히 같았다.** (시험을 시작할 때 `data/`에 내 결과가 이미 있었고, 앱 서버는 켜져 있지 않았다.)
- **로그인은 건드리지 않았다.** 실패 상황은 실제 Claude CLI를 망가뜨리지 않고 **가짜 `claude`**(`tests/fake_claude.py`)가 돌려주는 **모의 오류**(일시 오류 `529`, 검색 도구 오류, 느린 응답)로 만들었다.
- 가짜 `claude`는 실제 CLI와 같은 `stream-json` 형식으로 말하고, 앱은 그것을 실제 엔진과 같은 코드(`app/claude_engine.py`)로 처리한다. 즉 앱의 엔진 연결·저장·질문·재개 코드는 실제 경로를 지났고, **모델·네트워크만 가짜**다.
- 시험 도우미: [tests/validate_scenarios.py](tests/validate_scenarios.py) (실행 중인 서버에 HTTP로 조작). 화면 확인은 Claude 내장 브라우저로 직접 눌렀다.
- 집계: 시나리오 스크립트 **38개 확인 항목(단계 a 28 + 단계 b 10) 전부 통과**, 브라우저 직접 확인 4건(1-b, 2-b, 3-c, 5-b), 기존 자동 테스트 47개 통과.

## 시험 중 발견한 것 (요청한 5개 기대 결과 밖)

- **서버를 강제로 종료하면 실행 중이던 `claude` 하위 프로세스가 남았다(확인함) → 고쳤다.** 조사가 진행 중일 때 서버 프로세스를 강제 종료하자 가짜 `claude` 프로세스가 계속 떠 있었다(그때는 내가 직접 정리). 실제 `claude`였다면 서버가 사라진 뒤에도 작업이 계속되어 사용량을 쓸 수 있는 문제다. 수정과 확인 결과는 아래 "수정: 서버 강제 종료 시 하위 프로세스 정리"에 있다.
- (자동 테스트는 이 수정 뒤 50개: 위 47개 + 프로세스 보호 3개, 모두 통과.)
- 실제 Claude 엔진은 질문 여부를 매번 다르게 판단한다. 질문 흐름을 확실히 시험하려면 "독자를 항상 묻기" 설정이 필요하다(지금은 없다).

**고친 방법**: [app/procguard.py](app/procguard.py). 서버 프로세스를 Windows **Job Object**(`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`)에 넣는다. 서버가 만든 하위 프로세스는 자동으로 같은 작업에 속하고, 서버 프로세스가 어떻게든 사라져 작업 핸들이 닫히면 운영체제가 작업 안의 모든 프로세스를 종료한다. 서버 자신을 넣기 때문에 하위 프로세스를 띄운 뒤에 따로 붙이는 방식과 달리 빠져나가는 프로세스가 없다. 서버 시작 때 한 번 적용하고(`GET /api/health`의 `childProcessGuard`가 `job-object`이면 적용된 것), 실패하면 이유가 `failed: …`로 보이며 기존 정리(취소·시간 초과·정상 종료)는 그대로 동작한다.

**남은 한계**: Windows에서만 동작한다(다른 운영체제는 `unsupported-os`). 서버가 이미 중첩을 허용하지 않는 Job Object 안에서 실행되면 적용에 실패할 수 있다(Windows 8 이상은 중첩 허용). 정상 종료(Ctrl+C)는 이번에도 시험하지 않았다.

## 한계

- 이번 검증의 실패 상황은 모두 **가짜 `claude`의 모의 오류**다. 실제 Claude의 `529`/사용 한도/검색 장애 문구와 다를 수 있다.
- 카드·스토리보드·이미지 단계의 실패와 보존(4-c)은 처음에는 미구현이라 시험하지 못했고, 구현 뒤 2026-10-24에 가짜 도구로 다시 시험해 통과했다. 실제 엔진·실제 이미지 도구로는 시험하지 않았다.
- 두 개 이상의 브라우저 탭이나 두 사람이 동시에 조작하는 경우는 시험하지 않았다(3-c는 한 화면을 멈춰서 재현).
- 서버 재시작은 프로세스 강제 종료로만 시험했다. 정상 종료(Ctrl+C) 후 재시작은 시험하지 않았다.

```powershell
$t = "$env:TEMP\cardnews_validation"; New-Item -ItemType Directory -Force "$t\data","$t\state" | Out-Null

.\.venv\Scripts\python.exe run.py --port 8792
```
