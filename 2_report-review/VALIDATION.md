# VALIDATION — 확인한 것과 확인하지 못한 것

날짜는 모두 2026-10-24, 엔진은 Claude CLI(sonnet/medium). 날짜별 상세 기록은 `_제출제외/VALIDATION_full.md`에 있다.

## 1. 자동 테스트: 26개 통과 (가짜 claude)
`.\.venv\Scripts\python.exe -m unittest discover -s tests` — 실제 모델·네트워크·내 data를 쓰지 않는다. **모의로만 확인한 것**이다.

| 확인한 것 |
|---|
| 지적의 인용문이 글에 실제로 있다(없으면 고쳐 쓰게 하고, 그래도 없으면 분석 실패) |
| 제출 조건이 모델에 전달되고, 자료가 필요한 방향만 검색 도구를 쓴다 |
| 고른 문단만 바뀌고 나머지는 한 글자도 그대로(앱이 직접 비교) |
| 근거를 못 찾으면 고치지 않고 `⚠[자료 보강 필요]`와 필요한 자료를 남김(보류), 붙여 넣은 자료로 이어서 고침 |
| 지어낸 출처 주소·번호가 안 맞는 인용 거절, 근거에 없는 수치 경고 |
| 재검수가 "일부 해결"을 그대로 보고, 새 문제에 중요도가 붙음, 라운드는 최대 3번 |
| 검색 불가·로그인 필요·형식 오류·취소·서버 재시작에 원인과 다시 시도 방법을 보임 |

## 2. 실제 Claude로 확인한 것
- **전체 흐름**: 분석(지적 5개, 인용문 모두 글에 있음) → 방향 선택 → 실제 검색·원문 열람 → 그 문단만 수정 → 재검수 → 파일 저장.
- **자료 부족 경로**: 근거를 못 찾으면 글을 고치지 않고 "무엇을 확인하지 못했는지 / 필요한 추가 자료"를 문단별로 적었다. 지어낸 자료는 넣지 않았다.
- **붙여 넣은 자료**: 보류한 내용과 상관없는 자료는 쓰지 않았고, 오히려 글의 수치와 어긋난 점을 새 보류로 올렸다.
- **두 라운드 이어서 고치기**: 확인했다. 3라운드는 돌려 보지 못했다.

## 3. 확인하지 못한 것
- 붙여 넣은 자료가 보류한 주장을 **실제로 뒷받침하는** 경우(자료를 인용해 고치는 경로): 가짜 claude로만 확인.
- 출처 내용이 고친 문장을 정말 뒷받침하는지: 앱은 페이지를 다시 열어 대조하지 않는다. 사람이 확인해야 한다.
- 3번째 라운드, 긴 글(수만 자)의 처리 시간·비용, 로그인 만료 화면, 실제 Claude 취소.
- 브라우저: 복사 버튼이 실제로 클립보드에 들어가는지는 눌러 보지 않았다.
- 지적이 **내용상 맞는지**는 글쓴이가 판단한다. 앱은 형식·인용·근거만 검사한다.

## 5. 기대와 달랐던 사례 하나
- **기대**: 글쓴이가 주지 않은 이유·경험은 쓰지 않는다.
- **실제**: "봄을 알리는 꽃이기 때문이다 … 나에게 매화는 중요하다"를 글쓴이의 이유로 대신 써 넣었고, 재검수는 "해결"로 평가했다. 같은 문단 끝에는 "개인적 의미는 보류"라는 표시도 남아 서로 어긋났다.
- **바꾼 점**: 수정 프롬프트에 두 줄 추가 — 글쓴이만 아는 내용은 새로 쓰지 않는다, 보류의 `needed`에는 필요한 자료만 쓴다(DECISIONS R25).
- **다시 실행한 결과**(`rv_3207bcce21`): 글은 한 글자도 바뀌지 않았고 지적 2개 모두 `자료 부족`, 필요한 자료(언제·어디서 본 경험, 색·향, 느낀 점, "중요하다"의 의미)만 적었다.
- **한계**: 각각 한 번씩만 돌렸고 분석이 달라져 지적이 3개에서 2개로 바뀌었으므로 같은 지적끼리의 비교가 아니다. 프롬프트 덕분이라고 단정할 수 없다. 고친 문장이 하나도 없는 것은 근거 없는 글에서는 맞는 동작이지만 도움은 덜하다. 자동 테스트는 늘리지 않았다.
- **그 밖에 사용하면서 고친 것**: 화면 오류(`null` 글자, 상자 넘침, 글 잘림), 변경 표시·복사 버튼, 새 문제 이어서 고치기(라운드), 문단 나눔, 보류 목록 줄 나눔. 자세한 기록은 `_제출제외/VALIDATION_full.md`.

## 6. 알려진 남은 문제
- 보류만 있고 새 문제가 0개일 때도 결과 화면에 "아래 새 문제를 이어서 고치거나…" 안내가 뜬다(문구가 상태와 어긋남, 고치지 않음).
- 한 문단의 보류가 많으면 `final.md`의 `⚠` 표시가 길다. 화면·리포트의 목록은 항목별이다.
- 보류 표시가 남은 `final.md`를 그대로 제출하면 `⚠`가 보이므로 제출 전에 직접 보완하거나 지워야 한다.
- 제출에서 `data/`(내 PC 경로·실행 기록)와 `.venv/`는 뺀다.
